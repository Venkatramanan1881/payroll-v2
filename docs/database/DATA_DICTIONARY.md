# Data Dictionary — Package 1: Employee Master

Phase 3 artefact, companion to [DATA_MODEL.md](DATA_MODEL.md). Status: **Approved at Gate 3, 22 November 2026.**
Written from the migrations in `backend/crates/db/migrations/` (0001–0007). If this page and a migration disagree, the migration is the source and this page is fixed.

## How to read this

- **PK** = primary key. **FK** = foreign key (→ table it points to). **UQ** = unique. **NN** = NOT NULL.
- Every FK between client tables is composite `(org_id, x_id)` → `(org_id, id)` of the target, so a row can never point to another organisation's row. Below it is written as `→ table` for short.
- `uuid` keys default to `gen_random_uuid()`. `bigint` identity keys are generated by the database.
- **Standard columns** (marked *std* in the tables):
  - `created_at timestamptz NN default now()`
  - `created_by uuid`, default = the user set for the transaction
  - `updated_at timestamptz NN default now()`, set by trigger on every update
  - `row_version integer NN default 1`, the API adds 1 on every update (optimistic locking)
- **RLS** = row-level security on: the row is visible and writable only when `org_id` = the organisation set for the transaction.
- **Lifecycle** says how a row is born, changes and ends. Privileges say what the API is *allowed* to do (I = insert, U = update, D = delete; U(cols) = only those columns).

```
0001 foundation        schema app, btree_gist, roles app_api / app_outbox / app_vendor, helper functions
0002 platform          plans → organisations → vendor_users
0003 org structure     branches, departments, designations, categories, employee_types, exit_reasons,
                       contractors, payroll_groups, org_settings_versions, reference_name_history
0004 people            employees → employment_periods → employee_job_versions → job_version_allowed_branches
                       status_change_requests → employee_status_changes
                       employee_code_sequences, custom_field_definitions → custom_field_values,
                       bulk_imports → bulk_import_rows

                       permissions, roles → role_permissions, user_roles → user_role_scope_items
                       + FKs from status_change_requests and bulk_imports to users

```
